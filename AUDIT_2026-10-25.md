## 1. EXECUTIVE SUMMARY

Site is fast to serve (TTFB 40 ms, Vercel edge) but **not launch-ready**. Live homepage shows **18 visible "TODO:PROOF/TODO:CONFIRM" strings** and "Add photo" placeholders in place of instructors, testimonials, refund policy and gallery — a trust-killer for a skeptical buyer. **Plan CTAs dead-end**: `?plan=` is dropped by `/auth`, no checkout. **`hello@unifitz.in` cannot receive mail** (no MX record). **No analytics installed** — every `track()` call goes nowhere. **No Privacy/Terms/Refund pages** while collecting phone numbers with a **pre-ticked consent box**. SPA ships an empty `<div id="root">`: AI crawlers (GPTBot, ClaudeBot, PerplexityBot) see zero content; mobile LCP 5.5 s, partly because a **113 KB unused jsPDF chunk loads on the homepage** due to a `manualChunks` misconfig. Every non-existent URL returns 200 (soft 404) and `og-image.jpg` / favicon don't exist, so WhatsApp/social shares render without preview.

**🔴 Added after authenticated dashboard testing (Phase 16):** a **privilege-escalation hole lets any logged-in member make themselves admin** (the `profiles` UPDATE RLS policy has no `WITH CHECK`, so a user can PATCH their own `role` to `admin` with the public anon key and then read/edit all users, payments, revenue and leads). This is the single most urgent fix — ahead of everything below. Also: the `series_earnings` view leaks revenue to anonymous users, `email_exists` lets anyone enumerate accounts, and **all 31 recipe images are broken** (hotlinked to loremflickr, 500ing).

Fix order: **RLS escalation (P0, today)** → remove TODOs + wire real proof → MX/email → legal pages + consent → checkout flow → analytics → prerender + chunk fix → soft-404 + OG image → recipe images + dashboard a11y.

**Root causes**
1. **jsPDF + framer-motion preloaded on every page.** `index.js` does `import{_}from"./pdf-…js"` and `import{j}from"./motion-…js"`: Vite's object-form `manualChunks` dragged a shared helper into `pdf` and `react/jsx-runtime` into `motion`. [VERIFIED]
2. **Empty HTML** → nothing paints until ~300 KB gz JS downloads + parses + Landing chunk lazy-loads + framer fades H1 from opacity 0.
3. Four font families.

**Fixes**

`vite.config.js`:
```js
build: {
  rollupOptions: {
    output: {
      manualChunks(id) {
        if (!id.includes('node_modules')) return;
        if (/node_modules\/(react|react-dom|react-router|react-router-dom|scheduler|@remix-run)\//.test(id)) preturn 'react';
        if (id.includes('/@supabase/')) return 'supabase';
        if (/\/(recharts|d3-[a-z-]+|victory-vendor)\//.test(id)) return 'charts';
        if (id.includes('/jspdf/')) return 'pdf';
        if (/\/(framer-motion|motion-dom|motion-utils)\//.test(id)) return 'motion';
      },
    },
  },
},
```
Then confirm `dist/index.html` no longer has `modulepreload` for `pdf-*` / `motion-*`. Also make `lib/dietPdf.js` import jsPDF dynamically: `const { jsPDF } = await import('jspdf');`.

**Prerender `/`** (biggest win for FCP, LCP, SEO, AEO) — `scripts/prerender.mjs`, run after `vite build`:
```js
import { preview } from 'vite';
import { chromium } from 'playwright';
import { writeFile } from 'node:fs/promises';

const server = await preview({ preview: { port: 4173 } });
const browser = await chromium.launch();
const page = await browser.newPage();
await page.goto('http://localhost:4173/', { waitUntil: 'networkidle' });
const html = await page.content();
await writeFile('dist/index.html', html);
await browser.close();
server.httpServer.close();
```
`package.json`: `"build": "vite build && node scripts/prerender.mjs"`. `createRoot` replaces the static markup on boot, so no hydration mismatch. Remove `initial="hidden"` on hero H1/sub/CTAs so prerendered text doesn't blink out (use CSS `@keyframes` fade instead).

**Hero LCP:** don't animate LCP text from opacity 0. When a real hero photo ships: AVIF/WebP, `width/height`, `fetchpriority="high"`, **no** `loading="lazy"` (currently `PhotoInner` lazy-loads every image, including hero).

**Fonts:** keep 2 families (serif + sans used on landing), self-host via `@fontsource-variable/fraunces` etc., preload the one woff2 used in H1.

**Defer Supabase on landing:** fetch testimonials/reviews in `requestIdleCallback` or when `#proof` intersects.

### 16a. 🔴 CRITICAL — privilege escalation (any client → full admin)

The `profiles` UPDATE policy is:
```
own profile update | UPDATE | USING (id = auth.uid()) | WITH CHECK (none)
```
When `WITH CHECK` is omitted, Postgres reuses the `USING` expression as the check. The row's `id` doesn't change on update, so **a logged-in client can PATCH their own `role` to `admin`** and the check still passes. [VERIFIED on local DB: a client account's role flipped to `admin`.] Once admin, the `admin full profiles` policy (`USING get_my_role() = 'admin'`) lets them read/edit **every** profile, and every other admin-gated table opens up (users, revenue, leads/PII, payments, series). One ordinary member → full control of the business.

Reproduction (any authenticated client, with only the public anon key that already ships in the bundle):
```
PATCH /rest/v1/profiles?id=eq.<self>   body {"role":"admin"}   → 200
```

**Fix** — pin immutable columns in a `WITH CHECK`, and never let a self-update change `role`/`is_active`:
```sql
drop policy "own profile update" on public.profiles;
create policy "own profile update" on public.profiles
  for update to authenticated
  using (id = auth.uid())
  with check (
    id = auth.uid()
    and role = (select role from public.profiles where id = auth.uid())
    and is_active = (select is_active from public.profiles where id = auth.uid())
  );
```
(Or route profile edits through a SECURITY DEFINER RPC that whitelists editable fields.) Audit every other `for update`/`for all` policy in the repo for the same missing-`WITH CHECK` pattern. **Rotate assumption:** treat prod as potentially already escalated — scan `profiles` for unexpected `role='admin'` rows before/after the fix.

### 16b. Authorization — what is correctly locked down [VERIFIED]
Most policies are sound; the escalation above is the one hole, but it's fatal:
| Check | Result |

### 16c. 🟠 `series_earnings` view is world-readable
```
series_earnings is a VIEW; anon has SELECT (and the default blanket GRANT ALL)
```
The view exposes per-series **gross revenue, Unifitz cut and teacher payout**. A plain Postgres view runs with the definer's rights and **bypasses the RLS on the underlying `payments`/`challenges`**, so `anon` reading it leaks business financials. [VERIFIED: anon returned rows.] Seed amounts are 0 so nothing sensitive leaked in test, but in prod this is a revenue leak.
**Fix:** `alter view public.series_earnings set (security_invoker = on);` (PG15+) **and** `revoke all on public.series_earnings from anon;` plus a `grant select ... to authenticated` with the view filtering by `get_my_role()/is_my_challenge()`. Review the blanket `grant` that gave `anon` INSERT/UPDATE/DELETE on views/tables.
